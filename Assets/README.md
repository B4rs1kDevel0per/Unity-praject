# PS1 Style Pack — установка и настройка (актуальная версия)

Пак даёт три вещи:
1. **Материал-шейдер для объектов** (`PS1Style/VertexLitAffine`) — вертекс-снаппинг + аффинный
   плыв текстур + де-тайлинг швов.
2. **Общий постпроцесс** (`PS1Style/PostProcessDither`) — низкое внутреннее разрешение рендера +
   квантование цвета + дизеринг, накладывается на весь кадр сразу.
3. **Renderer Feature** (`PS1PostProcessFeature.cs`) — подключает постпроцесс в URP, написан под
   Render Graph API (актуальный пайплайн Unity 6 / URP 17+).

---

## 1. Точечная фильтрация текстур (обязательно, иначе всё смажется)
Для КАЖДОЙ текстуры в проекте: Inspector -> Filter Mode -> **Point (no filter)**.
На движке эффекты вертекс-снаппинга и низкого разрешения бессмысленны, если текстуры сглаживаются
билинейным фильтром — получится мыло вместо чётких пиксельных блоков.

## 2. Материал объектов — `PS1Style/VertexLitAffine`

1. Импортируй `Shaders/PS1_VertexLitAffine.shader`.
2. Создай материал, Shader -> **PS1Style -> VertexLitAffine**.
3. Настрой поля (актуальные названия и диапазоны):

| Поле в инспекторе | Диапазон | Что делает |
|---|---|---|
| **PS1 Vertex Snapping → Snap grid resolution** | 16–640, по умолч. 160 | Разрешение сетки, к которой "прилипает" геометрия каждый кадр. Меньше число = крупнее сетка = сильнее дрожание вершин (80 — очень олдскульно, 320+ — почти незаметно). |
| **Affine Wobble → Сила аффинного плыва** | 0–1, по умолч. 1 | 0 = обычная чёткая текстура (перспективная коррекция как обычно), 1 = максимальный PS1-плыв текстур на плоскостях под углом. Это СЛАЙДЕР силы, не переключатель — можно ставить любое промежуточное значение. |
| **SmartTiling → Включить** | галка, по умолч. выкл | Разбивает UV на клетки и случайно зеркалит каждую клетку — убирает видимую сетку швов на повторяющихся текстурах (пол, асфальт, обои). **Работает без новых швов только если сама текстура бесшовная** (см. п.4). |
| **SmartTiling → Размер клетки де-тайлинга** | 1–16 | Выставь примерно равным `Tiling X/Y` этого же материала — тогда одна "клетка" де-тайлинга = один повтор текстуры. |

4. Назначь материал на пропы/окружение.

### Если под ногами дикое искажение пола (affine на большом полигоне)
Аффинная ошибка UV растёт пропорционально размеру полигона. Если пол — один огромный `Quad`
(2 треугольника на всю комнату), искажение будет экстремальным. Решения (можно комбинировать):
- Используй `Plane` (уже 10x10 подсекций) вместо `Quad`, либо разбей пол на сетку из мелких плиток
  — так делали реальные PS1-игры.
- Заведи отдельный материал для пола/потолка с более низкой **Силой аффинного плыва** (0.1–0.3),
  а на мелких пропах оставь на максимум — там искажение почти не режет глаз.
- Или просто опусти **Силу аффинного плыва** глобально до 0.2–0.3.

### Про де-тайлинг швов (SmartTiling)
- **Обязательное условие:** исходная текстура должна быть реально бесшовной (левый край = правый,
  верх = низ). Если текстура не бесшовная — включённый SmartTiling даст ещё более уродливые швы,
  а не уберёт их. Если своей бесшовной текстуры нет — быстрый способ сделать: GIMP/Photoshop ->
  Filter -> Offset (сдвиг на половину ширины/высоты), после чего вручную подрисовать шов,
  оказавшийся посередине картинки.
- Дешёвая альтернатива без шейдера вообще: в Import Settings текстуры смени `Wrap Mode` на
  `Mirror` — работает слабее (эффект периодичен через 2 тайла), но не требует бесшовности.

## 3. Постпроцесс — `PS1Style/PostProcessDither` + Renderer Feature

1. Импортируй `Shaders/PS1_PostProcessDither.shader` и `Scripts/PS1PostProcessFeature.cs`.
2. Создай материал на основе шейдера `PS1Style/PostProcessDither`. Поля материала:
   - **Уровней цвета на канал** (`_ColorLevels`, 2–64) — 8-16 для сильного ретро-вайба, 32+ для
     более чистой картинки.
   - **Сила дизеринга** (`_DitherStrength`, 0–1) — насколько заметен узорный дизер поверх
     квантования цвета.
3. Открой свой `Universal Renderer Data` asset (Project window) -> Add Renderer Feature ->
   **PS1 Post Process Feature**.
4. В настройках фичи на объекте-фиче: `Dither Material` -> созданный материал, `Render Scale`
   -> начни с 0.35-0.5 (внутреннее разрешение рендера в долях от экранного — это одновременно и
   стилевой приём, и метод экономии FPS, замена FSR не нужна, см. п.6).

## 4. Материал постобработки (для Bloom/Motion Blur, если используешь)
Отдельно от этого пака — если используешь Volume-постобработку, ознакомься с системой настроек
графики (GraphicsApplier/SettingsManager из другого пака), там уже есть привязка к `Global Volume`.

## 5. Порядок отладки
Если картинка выглядит "слишком чисто" — сначала уменьшай `Render Scale` (постпроцесс), потом
`Уровней цвета` (дизеринг), и только потом `Snap grid resolution` у объектов (он сильнее всего
бросается в глаза, если переборщить).

## 6. Почему без FSR/DLSS
Внутреннее разрешение рендера уже занижено (`Render Scale` в фиче), а апскейл на экран идёт через
Point-фильтр (`FilterMode.Point` в `PS1PostProcessFeature.cs`) — это одновременно и стилевой приём
(чёткие пиксельные блоки вместо мыла), и метод экономии производительности (меньше пикселей = меньше
нагрузка на фрагментный шейдер). FSR/DLSS решают обратную задачу — реконструируют резкость из
низкого разрешения, что визуально конфликтует с намеренной пиксельностью PS1-стиля.

## 7. Про Render Graph (Unity 6 / URP 17+)
В Unity 6 URP по умолчанию использует новый Render Graph API — старые методы `OnCameraSetup`/
`Execute` в `ScriptableRenderPass` устарели и не переопределяются (ошибка CS0115, если написать их
вручную). `PS1PostProcessFeature.cs` уже написан под актуальный API (`RecordRenderGraph` +
`AddBlitPass`) — ничего дополнительно включать не нужно.

## 8. Атласы текстур и производительность (кратко)
- Прирост FPS от атласов идёт не от "текстура большая = быстрее", а от того, что общий материал
  на многих объектах даёт МЕНЬШЕ draw call'ов (batching). Размер атласа сам по себе почти не влияет
  на стоимость сэмплирования (решает mip-уровень, не общий размер файла).
- **Тайлящиеся текстуры (пол, асфальт, обои) НЕ клади в общий атлас** — Wrap=Repeat в атласе
  утаскивает выборку в соседние картинки атласа вместо повторения самой текстуры. Держи их
  отдельными текстурами/материалами с обычным Repeat/Mirror.
- Для не-тайлящихся мелких пропов — объединяй в 1-2 атласа по 1024–2048px на категорию (не 8k —
  для текселей 64-128px этого с огромным запасом хватит, а VRAM экономится в разы).

## 9. Частые ошибки при правке шейдеров руками (ShaderLab)
Если будешь сам дописывать свойства в `Properties { }` — три грабля, на которые мы уже наступали:
- `[Header(...)]` не любит не-ASCII символы вроде длинного тире `—` внутри самого атрибута
  (в кавычках-строках кириллица работает нормально, а вот тут — нет). Пиши Header латиницей.
- У каждого свойства обязателен ТИП: `_Имя ("Название", Тип) = значение`. Забытый тип
  (например `[Toggle] _X ("Название") = 0` без `, Float`) даёт ошибку "unexpected ')', expecting ';'".
- После правки файла в Unity — если ошибка не пропадает, а номер строки/текст ошибки точь-в-точь
  совпадает с прошлым разом, скорее всего файл физически не обновился на диске. ПКМ на файле ->
  **Reimport**, и при сомнениях — удали старый файл и добавь заново, а не перезаписывай.
